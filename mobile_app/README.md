# Nadeem Electronics Android app

This is a separate Flutter project. It opens the live Flask website at
`https://nadeemelectronics.pythonanywhere.com/` in an Android WebView; it does
not copy or replace the Flask backend. No existing Flask files need to change.

## Install the tools

1. Install the current stable Flutter SDK and add its `bin` directory to
   `PATH`.
2. Install Android Studio and its Android SDK, platform tools, and a recent
   Android SDK platform. Android Studio also provides the Android emulator.
3. Install the **Flutter** and **Dart** extensions in VS Code.
4. Use a JDK supported by the installed Flutter/Android Gradle Plugin (JDK 17
   is suitable for current Flutter Android projects).
5. Use Flutter 3.24 or newer (Dart 3.5 or newer). In a new VS Code terminal,
   check `flutter doctor` and resolve any Android toolchain issues it reports.

## Project structure

```text

|   `-- main.dart                 # WebView, navigation, offline UI, downloads
|-- tool/
|   |-- prepare_android.ps1       # Generates Android scaffold and applies config
|   `-- android/                  # Manifest, app label, placeholder icon
|-- pubspec.yaml
|-- README.md
|-- android/                      # Generated by prepare_android.ps1
`-- build/                        # Generated by Flutter APK builds
```

## Prepare and run in VS Code

Open the `mobile_app` folder in VS Code. Generate the standard Android
Gradle-wrapper and native project files once, and apply this app's Android
manifest, label, and placeholder launcher icon:

```powershell
.\tool\prepare_android.ps1
flutter pub get
flutter devices
flutter run
```

If PowerShell blocks the script, run it with a one-time execution-policy
override:

```powershell
powershell -ExecutionPolicy Bypass -File .\tool\prepare_android.ps1
```

Connect an Android phone with USB debugging enabled or start an emulator before
running `flutter run`. The website, login session, and server-side data remain
on PythonAnywhere. JavaScript and browser storage are enabled for the existing
site, and the Android back button goes back within the website before exiting
the app.

## Build and install an APK

Build a debug APK for testing:

```powershell
flutter build apk --debug
```

Build a release APK:

```powershell
flutter build apk --release
```

The APKs are generated under
`build\app\outputs\flutter-apk\` (`app-debug.apk` and `app-release.apk`).
Install a built APK on a connected phone with:

```powershell
adb install -r .\build\app\outputs\flutter-apk\app-debug.apk
```

For a release build, use `app-release.apk` in that command instead. On a phone,
allow installation from the file manager/browser used to open the APK if
Android asks. The release build uses Flutter's default local signing unless a
release signing key is configured; configure and protect your own signing key
before publishing or distributing updates.

## Website features and permissions

- Internal HTTPS pages stay in the WebView; other links open in the phone's
  browser or the appropriate app.
- Web forms use Android's native file chooser, including supported camera
  capture options provided by the device. Downloads are fetched with the
  WebView's website cookies and saved using Android's save-file dialog.
- The app requests only `INTERNET` and `ACCESS_NETWORK_STATE`. It does not
  request broad storage or camera permissions.
- Loading, retry, and no-connection screens are provided. Orientation changes
  are allowed so the website can adapt to the phone or tablet layout.
- There is no logo file in the existing Flask project's static images, so the
  app currently uses a simple electronics placeholder. Replace
  `tool\android\ic_launcher.xml` with your logo in Android Vector Drawable form
  (or adapt the manifest/icon resources for PNG/adaptive icons), then rerun
  `.\tool\prepare_android.ps1` to apply it.

## Future website updates

Update and deploy the Flask website to PythonAnywhere as usual. The APK always
loads the live URL, so website content and server-side changes appear without
rebuilding or reinstalling the app. Rebuild the APK only when changing the
Flutter/Android app itself, such as the website URL, native icon, permissions,
or app behavior.

## Existing project safety

Keep this folder separate from the Flask app. The Android preparation script
generates Android scaffolding in a temporary directory and copies only the
generated `android` folder into this Flutter project; it does not modify the
Flask project's routes, database, templates, styles, scripts, or Python files.
